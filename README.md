# GOLF GUTS PUTTING MONSTERS

実際のパター練習と連動するモンスターバトルゲーム（開発中）。
iPhone のカメラで実際のゴルフボールを認識し、速度を測ります。

**現在の状態：Phase 1（カメラ計測）**
ボールの検出・追跡・速度計算・校正・計測ログまでを実装しています。9フィート換算の推定距離（Phase 2）とモンスターバトル（Phase 3）は未実装です。

> **実機での動作は未確認です。** シミュレーション映像と PC のブラウザでは確認していますが、iPhone の実カメラでの計測は、下の「実機検証手順」で確認してください。

## 同じアカウントの他のアプリとの共存

GitHub Pages では、同じアカウントのアプリ（メトロノームなど）はすべて `hm08050710670-jpg.github.io` という同じサイトとして扱われ、端末内の保存場所（localStorage とキャッシュ）を共有します。他のアプリのデータを壊さないよう、次のようにしています。

- 保存データの名前にはすべて `ggpm.` を付け、読み書き・削除はこの名前のものだけを対象にする（`js/storage.js`）
- キャッシュの名前にはすべて `ggpm-` を付け、古いキャッシュの掃除もこの名前のものだけを対象にする（`sw.js`）
- Service Worker の担当範囲はこのアプリのフォルダ（`/putting-monster/`）の中だけ

PC のブラウザで、別アプリのデータとキャッシュを先に置いた状態からこのアプリを使い、「このアプリの保存データを消去」と更新を行っても、別アプリ側が変化しないことを確認しています。今後ファイルを変更するときも、この2つの接頭辞のルールは守ってください。

なお、保存容量（約 5MB）もサイト全体で共有です。このアプリの計測ログは最大 300 件（1MB 未満の見込み）に制限しています。

## GitHub Pages で公開する

1. GitHub で新しいリポジトリを作る（公開設定は Public）。
2. このフォルダの中身を、フォルダ構成を保ったままリポジトリの直下に置く。
3. リポジトリの **Settings → Pages** を開く。
4. 「Build and deployment」の Source を **Deploy from a branch**、Branch を **main / (root)** にして Save。
5. 1〜2 分後、`https://ユーザー名.github.io/リポジトリ名/` で開けます。

インストール作業（npm install など）は不要です。

### iPhone だけで置く場合の注意

GitHub の Web 画面のアップロードは、iPhone ではフォルダごとの選択ができない見込みです（未確認）。その場合は次のどちらかになります。

- フォルダごとに「Add file → Upload files」を繰り返す（`js/core/` など、フォルダは「Create new file」でファイル名に `js/core/名前.js` と入力すると作れます）
- git が使えるアプリ（Working Copy など）を使う

ファイルを追加・削除したときは、`sw.js` の `VERSION` と `FILES` も更新してください。

## iPhone で使う

1. **Safari** で公開アドレスを開く（アプリ内ブラウザでは動かないことがあります）。
2. 「測定テスト」または「キャリブレーション」を開くと、カメラの使用許可を求められます。「許可」を選びます。
3. 共有ボタン →「ホーム画面に追加」で、アプリのように起動できます。

カメラを拒否してしまった場合は、画面に表示される手順で許可し直してください。

カメラがなくても、「カメラ設定 → 映像ソース → シミュレーション映像」で一連の流れを試せます。シミュレーションの値は実測ではなく、画面とログに必ずその旨が表示されます。

## 設置と校正の手順

アプリ内の「遊び方・設置方法」にも同じ内容があります。

### 用意するもの

- 緑や濃い色のパターマット、白いボール
- iPhone を固定する三脚
- 目印 6 個（白以外の色付きシールなど）、メジャー

### 目印

- ボールを置く位置から **30cm 以上先**をスタートラインにする（打った直後の滑りを避けるため）
- スタートライン、75cm 先、150cm 先の、それぞれマットの左右に目印を置く（計 6 個、長方形になるように）
- 左右の間隔、スタート〜ゴールの間隔を測る

### カメラ

- マットの横 1.5〜2m、高さ 1m 以上から見下ろす。打つ人の反対側に置く
- 6 個の目印がすべて画面の内側に映るようにする
- 1x カメラを使う（0.5x の広角は歪みが大きい）
- 部屋を明るくする
- 設置後は動かさない

### キャリブレーション

1. 「キャリブレーション」→「静止画を撮って基準点を合わせる」
2. 丸印をドラッグして目印の中心に合わせる（拡大表示と矢印ボタンで 1px 単位の調整）
3. 寸法とカメラの高さを入力
4. 画面下の確認項目を見る
   - **6点の食い違い**：4mm 以下が目安。大きい場合は点の位置か寸法を見直す
   - **映像から推定したカメラの高さ**：入力値と大きく違う場合は、どこかが間違っている
   - **ボールの見かけの直径**：処理時 6px 以上が必要
5. 「この内容で保存」

カメラが動いた場合や、解像度・iPhone の向きを変えた場合はやり直しが必要です。キャリブレーション画面を開くと、保存済みの枠が現在の映像に重ねて表示されるので、ずれを目で確認できます。

## 実機検証手順

iPhone で次の順に確認し、結果を記録してください。うまくいかない項目があれば、その画面の表示内容（数値）を教えてください。

### A. カメラの基本動作

「カメラ設定 → カメラ診断を実行」

| 確認項目 | 記録する値 |
|---|---|
| 映像が表示されるか | はい／いいえ |
| 実測 fps（「使用中」の行） | 例：59.8 |
| 使用中の時刻の種類 | captureTime／mediaTime／presentationTime／受信時刻 |
| ばらつき (SD) | 例：0.4 ms |
| 端末が申告するフレームレートの上限 | 例：60 |

60fps が出ない場合は、部屋を明るくして再実行します。

### B. ボールの検出

1. キャリブレーションを済ませる
2. 「測定テスト」を開き、「検出表示」をオン
3. 測定範囲内にボールを置く → ボールだけが黄色く表示され、「ボール認識」の丸が付くか
4. ボールを取り除く → 黄色い表示が残らないか

ボール以外が黄色くなる場合は、「カメラ設定 → ボール検出の調整」で明るさのしきい値を上げます。

### C. 速度の計測

1. 「計測開始」→「準備完了」の音声を待つ
2. 打つ → 速度が表示・読み上げされるか
3. 同じ強さのつもりで 10 球打ち、有効／無効の数、速度のばらつき、信頼度を見る
4. 画面下の表示で、処理時間（ms）と fps を見る

### D. 精度の確認（重要）

速度の真値を別の方法で用意して比べます。

- **方法 1（停止距離）**：弱めに打ち、ボールをマット上で自然に止める。スタートラインから停止位置までをメジャーで測り、「計測ログ」に記録する。同じマットなら「入口速度² ÷ 停止距離」がほぼ一定になるはずです。ばらつきが大きければ、計測か校正に問題があります。
- **方法 2（スロープ）**：一定の高さから坂を転がして毎回同じ速さで範囲に入れ、計測値が毎回そろうかを見る。
- **方法 3（別撮り）**：別の端末でスローモーション撮影し、目印間の通過時間から速度を求めて比べる。

「計測ログ → CSV を書き出す」で、数値を表計算ソフトに取り込めます。

### E. 誤検出の確認

- ボールなしで範囲の近くを歩く、パターを素振りする → 結果が出ないこと
- 白い靴・白い手袋・白いパターを使う場合 → 誤った結果が出ないか

PC がない場合：`.github/workflows/test.yml` を置いておくと、GitHub に上げるたびに同じテストが自動で走り、リポジトリの「Actions」タブで結果を見られます（この設定ファイル自体は GitHub 上では未確認です）。

## 既知の制約

**環境に関するもの**

- 60fps は保証されません。暗いと iOS が自動でフレームレートを下げます。
- 露出・シャッター速度は固定できません。暗いとボールがぶれ、検出が不安定になります。
- レンズ歪みは補正していません。
- 白っぽい床・マットの上では、白いボールを検出できません。
- 白いパターヘッド・手袋・靴が測定範囲に入ると誤検出の原因になります（追跡と有効性の判定で多くは除外しますが、完全ではありません）。
- ホーム画面に追加したアプリでは、起動のたびにカメラの許可を聞かれることがあります。
- アプリを背面に回すとカメラが止まります。戻ったときに自動で取り直し、計測は停止状態に戻ります。

**計測に関するもの**

- 校正が間違っていても、個々の結果の「信頼度」には現れません。信頼度は追跡と当てはめの品質だけを見ています。校正の良し悪しは、校正画面の「6点の食い違い」と実機検証 D で確認します。
- カメラが動いたことの自動検出はありません（キャリブレーション画面で枠のずれを目で確認）。
- 打ち出し直後の滑りが測定範囲に入ると、入口速度に数%の誤差が出ることがあります（スタートラインをボールから離すと避けられます）。
- 減速度は 1 打ごとの誤差が大きく、参考値です。複数回の平均で使う想定です。
- 色付きのボールには対応していません。
